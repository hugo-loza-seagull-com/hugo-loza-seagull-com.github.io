LLM core model

Large Language Models predict and compose text, code, and structured outputs. They power reasoning, summarization, and generation workflows.

Language understanding

MCP protocol

Model Context Protocol connects models to external systems safely and consistently, exposing tools, resources, and prompts through a standard interface.

Model→MCP Server→Tools/Data

Agent executor

An agent plans steps, chooses tools, executes actions, and adapts from results to complete goals with less human micromanagement.

Plan→Act→Observe→Refine

Skills reusable ability

Skills package domain-specific behavior (analysis, extraction, transformation) so the agent can invoke proven mini-workflows quickly.

Tools action layer

Tools let models do work beyond text: query APIs, edit files, run checks, and fetch data. Reliable tooling is key to dependable outcomes.

Agenting operating mode

Agenting is the practice of orchestrating autonomous loops around goals, guardrails, and evidence-driven decision making.

SDD spec-first method

Spec-Driven Development defines expected behavior before implementation so requirements, constraints, and acceptance criteria stay explicit and testable.

Define Spec→Implement→Validate

ReAct reason + action loop

ReAct combines deliberate reasoning with focused actions in short cycles, helping teams adapt quickly based on observed outcomes and evidence.

Reason→Act→Observe→Adjust

Prompt instruction unit

A prompt defines task, context, constraints, and expected format. Clear prompts reduce ambiguity and improve consistency.

Prompt Engineering design craft

Prompt engineering optimizes intent expression: role framing, context layering, examples, and output contracts for predictable behavior.

Loop Engineering feedback cycle

Loop engineering builds robust iterative cycles: generate, evaluate, repair, and retry with stop conditions and quality thresholds.

Generate↺Evaluate↺Improve

Harness Engineering reliability shell

Harness engineering provides scaffolding around agents—tests, telemetry, policy checks, and observability—to make systems safe and repeatable.
